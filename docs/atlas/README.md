# Atlas

Operational memory for this project. The session-start hook loads the current
state into the agent's context directly; the `using-atlas` skill carries the
rules for writing to it.

## Layout

```
docs/atlas/
├── VERSION                 the store's format version; absent means v1
├── ROADMAP.md              current milestone (one section only)
├── design/                 one file per grill round: decided, and still open
│   └── YYYY-MM-DD-slug.md  written once, not edited afterwards
├── records/                everything remembered, one counter for all types
│   ├── _index.md           auto-generated browse view
│   └── NNN-slug.md
└── archive/                frozen, superseded layouts kept for grep
    ├── journal/            the pre-record work log
    └── v1-id-map.tsv       pre-v2 identifiers → the records they became
```

## Design documents

One file per round of grilling under `design/`, holding **Decided** and **Still
open**, written once by `grill-me` and not edited afterwards. That is what makes
it safe to commit: it is a dated account of what one round settled, which stays
true however the code moves. There is no work log, no status, and nothing to
close.

A grill crosses one gap — vague to decided — and the gaps do not come in a fixed
set. Clarifying a requirement, settling a product's form, settling how a module
is built, ordering the steps: each is one round, and the level is named in the
title rather than imposed as a schema. A round that settled a design and reached
no implementation is complete without a plan in it. Spec and design are not two
kinds of thing: what one round chose among alternatives is what the next round
must satisfy.

Each Decided item carries the source of the verdict on it — a reference
implementation, an invariant, data whose answers are known independently, a
failure that happened, values the user gave. An item whose only source is the
code under test is a characterization test and must say so.

**Still open means "as of this date."** Nothing closes those entries and nobody
returns to tick them off; a later round settling one is a later document. The
test for an entry is that it could seed the next round.

Documents name the one they continue, and stay flat: rounds branch, and a later
round may draw on two earlier ones, which is a graph and not a tree. They do not
load at session start — `ls docs/atlas/design/` is the menu when one is wanted.

What outlives the round goes to the store. What is only how this task got done
stays in Decided.

## The record store

One file per record. Frontmatter carries identity only — `id`, `title`,
`date`, `type`, `tags` — and experiments add five one-line machine summaries.
The body carries the prose and every relation.

Four types, with `type` an ordinary field that can be corrected later:

| type | holds |
|---|---|
| `memory` | a constraint in force; title always loaded, rewritten in place |
| `experiment` | a measurement and what it showed |
| `decision` | a choice and the alternative it beat |
| `question` | something unresolved |

## Conventions

- **State is derived.** There is no status field. Superseded, refuted and
  answered are computed from the typed edges pointing at a record, so nothing
  has to be remembered and updated later.
- **Relations live in the body**, in Obsidian syntax: `[[NNN-slug]]` for a
  reference, `(refutes:: [[NNN-slug]])` for a typed edge, written into the
  sentence carrying the reasoning. Verbs are `supersedes`, `refutes`,
  `answers`; validate rejects any other.
- **Links point backwards.** A record only cites records that already existed.
  Memory records are exempt — they hold what is true now.
- **The commit is the publication boundary.** Before it a record is a draft
  and may be rewritten freely; after it, a newer record supersedes it. Adding
  a typed edge to a published record is the one permitted touch, since it
  changes nothing the record claims.
- **Numbers are never reused**, so an old link keeps its meaning.
- **`_index.md` is derived**, human-only, regenerated by `reindex.py` and
  deterministic. Do not hand-edit. The agent reads records, not the index.
- **The store is checked after every write.** A `PostToolUse` hook validates
  and reindexes whenever a tool call changed a record, because most writes are
  ordinary edits that no script owns — a memory record rewritten in place, a
  typed edge appended to a published one. A link that resolves to nothing is
  not a lint: the relation it expresses simply never happens.
- **Atlas changes ride the work unit's own commits** — no standalone "update
  atlas docs" commits unless the records are themselves the work.
- **The store declares its format.** `VERSION` holds a number, and every script
  refuses a store it does not match. This is not pedantry: an unmigrated store
  reads as an empty one, so without the check a project with months of memory
  loads as having none, and validate agrees. One migration script per version
  step, named for the step; run it on a copy and diff before applying.

## Operations

| Want to | Action |
|---|---|
| Start a session | the SessionStart hook loads state; the agent invokes `atlas:using-atlas` |
| Write a record | `atlas-entity/scripts/new.py`, one call, body on stdin |
| Think through anything non-trivial | `atlas:grill-me` — one document per round under `design/` |
| Rename a record | `atlas-entity/scripts/rename.py` — never by hand, links resolve by filename |
| Check the store | `atlas-entity/scripts/validate.py` |
| List or audit records | `atlas:atlas-entity` |
| Periodic maintenance | `atlas:atlas-compact` |
| Set a project up on atlas | `atlas:atlas-bootstrap` — once, whether the project is new or has history |
