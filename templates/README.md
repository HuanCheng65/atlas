# Atlas

Operational memory for this project. Maintained jointly by you and your agent
via the `atlas-*` skills under `~/.claude/skills/`. The agent enters atlas
at session start through the `using-atlas` skill (auto-loaded when
`CLAUDE.md` mentions `docs/atlas/`).

## Layout

```
docs/atlas/
├── ROADMAP.md              current milestone (one section only)
├── _templates/             entity templates (edit to change schema)
│   ├── decision.md
│   ├── experiment.md
│   └── question.md
├── journal/                work units; opened / appended / closed via atlas-log
│   ├── _index.md           auto-generated
│   └── YYYY-MM-DD-slug.md
├── decisions/              D-NNN: long-term architectural choices
│   ├── _index.md           auto-generated by atlas-entity/scripts/reindex.py
│   └── D-NNN-*.md
├── experiments/            E-NNN: research runs (research projects only)
│   ├── _index.md
│   └── E-NNN-*.md
├── questions/              Q-NNN: open questions
│   ├── _index.md
│   └── Q-NNN-*.md
└── topics/                 free-form long-form notes; emerge from journal patterns
    └── *.md
```

## Conventions

- One file per work unit in `journal/` — opened, appended, and closed via
  `atlas-log` scripts. All timestamps come from `datetime.now()` inside the
  scripts (never agent-fabricated).
- Entities (D / E / Q) are mutable but their schema is enforced by
  `atlas-entity/scripts/validate.py`. Naming rules live in the templates
  and in `atlas-entity/SKILL.md`.
- Decisions carry a `triage` state: `pending` (shown in orient's menu until
  reviewed), `promoted` (a one-line rule in PROJECT.md's **Working rules**
  section with a `(D-NNN)` pointer — `validate.py` enforces the pairing both
  ways), or `archival` (event record, consulted on demand). The decision log
  is the archive; the constitution in PROJECT.md is the always-loaded rulebook.
- `_index.md` files are derived, human-only browse views. Regenerated by the
  corresponding `reindex.py` (auto-run inside `open.py` / `append.py` /
  `close.py` / `new.py`); content is deterministic (no run-date dependence).
  Agent-facing reads (orient) parse frontmatter directly. Do not hand-edit.
- Templates define schema and naming rules. To change either, edit
  `_templates/` and re-run `validate.py`.
- Atlas data changes ride the work unit's own commits — no standalone
  "update atlas docs" commits unless the atlas content is itself the work.

## Operations

| Want to | Skill / action |
|---|---|
| Start a session | `using-atlas` runs automatically |
| See current state | `atlas-orient` |
| Record a long-term decision | `atlas-entity` (type=D) |
| Record an experiment | `atlas-entity` (type=E) |
| Note an open question | `atlas-entity` (type=Q) |
| Track work as it happens | `atlas-log` (open / append / close) |
| Plan a non-trivial task | `grill-me` |
| Periodic review / topic distillation | `atlas-compact` (planned) |
